# DAYCORD — DC-001

## Architecture Decision Record

**Проект:** Daycord

**Статус:** Accepted согласно постановке DC-002

**Назначение:** Зафиксировать архитектурную основу приложения и границы ответственности проектов.

## 1. Общая архитектура

Daycord — локальное кроссплатформенное desktop-приложение на .NET 10 и Avalonia UI 12.

Архитектура — модульный монолит с разделением на три проекта.

Формат Solution: Daycord.slnx.

Проекты:

1. Daycord.Core
2. Daycord.Infrastructure
3. Daycord.Desktop

Единственная точка входа находится в Daycord.Desktop.

## 2. Направления зависимостей

Daycord.Infrastructure зависит от Daycord.Core.

Daycord.Desktop зависит от Daycord.Core и Daycord.Infrastructure.

Daycord.Core не зависит от остальных проектов.

Циклические зависимости запрещены.

## 3. Daycord.Core

Проект содержит чистые C#-типы предметной области.

Основные сущности:

### TaskItem

Представляет пользовательскую задачу.

Свойства:

- Id: Guid
- TaskDate: DateOnly
- Title: string
- ShortDescription: string?
- DescriptionMarkdown: string?
- StatusId: Guid
- CreatedAtUtc: DateTime
- UpdatedAtUtc: DateTime
- CompletedAtUtc: DateTime?

TaskDate — основная дата задачи.

Изменение TaskDate не изменяет автоматически записи планирования и фактической работы.

### TaskStatusDefinition

Статусы хранятся в отдельной сущности и таблице `TaskStatuses`.

Свойства: `Id: Guid`, `SystemKey: string?`, `Name: string`,
`IsSystem: bool`, `IsCompleted: bool`, `SortOrder: int`.

Предустановленные статусы:

- `open` / Open / `5e8a148e-1a3b-4b17-bba6-251392a01d61` / не завершён;
- `completed` / Completed / `b9436dc3-7247-4d9e-a032-2a9cb1b9c7a8` / завершён.

В модели предусмотрены пользовательские статусы (`SystemKey = NULL`),
но экран их настройки будет реализован в следующих задачах.

### PlanningPeriod

Представляет отдельную запись запланированного времени.

Свойства:

- Id: Guid
- TaskId: Guid
- PlannedDate: DateOnly
- PlannedMinutes: int

Одна задача может иметь несколько периодов планирования, включая несколько периодов на одну дату.

PlannedMinutes должен быть положительным целым числом.

Отсутствие плана означает отсутствие записи PlanningPeriod.

### WorkEntry

Представляет отдельную запись фактически выполненной работы.

Свойства:

- Id: Guid
- TaskId: Guid
- WorkDate: DateOnly
- ActualMinutes: int
- WorkDescription: string?
- Note: string?
- CreatedAtUtc: DateTime
- UpdatedAtUtc: DateTime

ActualMinutes должен быть положительным целым числом.

Фактическая работа независима от планирования.

Отчётные часы рассчитываются исключительно из WorkEntry.

## 4. Принципы доменной модели

- Длительности представлены целыми минутами.
- Планирование не создаёт фактические записи.
- Фактическая работа не изменяет план автоматически.
- TaskItem, PlanningPeriod и WorkEntry являются отдельными сущностями.
- Даты пользовательских записей представлены DateOnly.
- Технические временные метки представлены DateTime с семантикой UTC.
- Markdown-описание сохраняется как исходный текст.
- Доменные классы не зависят от Avalonia, SQLite или Dapper.

Проверки пользовательского ввода и операций сохранения относятся к следующим задачам.

## 5. Daycord.Infrastructure

Проект отвечает за техническую инфраструктуру приложения.

Утверждённый стек хранения:

- SQLite.
- Dapper 2.1.89.
- Microsoft.Data.Sqlite 10.0.13.

EF Core не применяется.

### Миграции

Используются версионированные SQL-скрипты.

В DC-003 реализованы автоматические миграции при старте приложения.
SQL-скрипты являются EmbeddedResource. История `__SchemaMigrations`
хранит версию, имя, SHA-256 и UTC-время применения. Несовпадающие checksum,
неизвестные и более новые версии приводят к безопасному отказу от запуска.
Одна транзакция охватывает SQL и записи об исполнении; при ошибке выполняется rollback.

### Локальные данные

SQLite-файл `daycord.db` расположен в `LocalApplicationData/Daycord`:
на macOS `~/Library/Application Support/Daycord`, на Windows `%LOCALAPPDATA%\Daycord`.
Guid хранится как TEXT в формате D; DateOnly — `yyyy-MM-dd`;
DateTime — текст ISO 8601 UTC, bool и целые минуты — INTEGER.
Подключения короткоживущие с foreign keys ON и тайм-аутом; Dapper type handlers
централизованы в Infrastructure.

### Excel

Для формирования ежемесячных Excel-отчётов используется ClosedXML.

Источником фактически отработанного времени являются WorkEntry.

### Резервное копирование

В DC-003 реализованы только защитные копии перед обновлением схемы.
Копирование через SQLite Backup API защищает файлы даже при активном WAL.
Копии находятся в `Backups/SchemaUpgrades` и не удаляются автоматически.
Пользовательский экспорт/импорт остаётся отдельной задачей DC-014.

## 6. Daycord.Desktop

Проект отвечает за пользовательский интерфейс.

Технологии:

- Avalonia UI 12.
- CommunityToolkit.Mvvm.
- Microsoft.Extensions.DependencyInjection.

Паттерн интерфейса — MVVM.

ViewModels не выполняют прямые SQL-запросы.

Composition Root находится в Daycord.Desktop.

На этапе DC-002 контейнер DI создаётся через ServiceRegistration.

Главное окно получает MainWindowViewModel через конструктор и DI.

В DC-003 добавлен асинхронный вызов `IDatabaseInitializer` после открытия окна.
До успеха показывается состояние инициализации; ошибка не разрешает работу с БД.
Отдельный HTTP-backend не используется.

## 11. Реализация DC-003

- Используется одна файловая SQLite-база; отдельно работающего сервера нет.
- `TaskItem.StatusId` ссылается на `TaskStatusDefinition.Id`.
  Старое перечисление `TaskStatus` удалено.
- `001_InitialSchema.sql` создаёт четыре предметные таблицы, индексы и
  два системных статуса с постоянными Guid.
- CHECK ограничивает положительную длительность планирования и фактической работы,
  непробельные имена статусов, допустимые значения bool и политику SystemKey.
- FK включены для каждого подключения, все зависимые удаления — RESTRICT.
- Миграции защищены SQLite IMMEDIATE-транзакцией, контролем SHA-256,
  проверками целостности и согласованной копией до обновления существующей базы.
- Повторный запуск не повторяет миграции и не перезаписывает пользовательские данные.
- Интерфейс остаётся нативным Avalonia с Graphite & Amber; язык по умолчанию английский.
  Полная RU/EN локализация будет разработана отдельно.
- Полноценные CRUD и пользовательские экраны не входят в DC-003.
